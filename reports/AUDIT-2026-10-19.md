# SIGNAL-X — Algorithm audit (2026-10-19)

**Scope:** engine math, causality/lookahead, live snapshot semantics, sentinel state machine,
runtime health, and the empirical verdicts in `reports/`.
**Method:** code review + independent recomputation (pandas/NumPy) on live Binance 5m data
(499 closed BTCUSDT/ETHUSDT/SOLUSDT bars fetched through the running API), prefix and
future-mutation causality tests, production journal/log analysis, API latency probes.
**Repro scripts:** `/tmp/opencode/audit_engines.py`, `/tmp/opencode/audit_pass2.py`.
No code was modified and no services were restarted during the audit.

## Verdict

- **Engine math: sound.** EMA and AVWAP match an independent implementation exactly; RSI/ATR
  match to ~4e-7 after warmup. All pivot/structure/divergence outputs are causal (verified by
  prefix and future-mutation tests).
- **Trading edge: none, by measured evidence.** G0 full-universe (−0.30%/trade @2× costs) and
  H1 (+0.037% vs +0.40% gate) both KILLed. The tool is correctly labeled observation-only.
- **Signal pipeline: not running.** Sentinel/recorder/CVD/book/stream/watchdog have been down
  since **Oct 17 20:24 UTC** — the journal is 52.7 h stale.
- **State machine: semantically wrong for a bar-based system.** It steps once per *poll*, not
  once per closed bar: 4 transitions completed on one identical snapshot in 4 consecutive
  sweeps, and timeouts are counted in evaluations (~84 min) instead of bars (300 min on 5m).
  `IN_TRADE` is terminal — `trade_closed` is hardcoded `False`, so a symbol emits at most one
  signal forever.
- **Event semantics: stale by construction.** `BEARISH_DIVERGENCE` means “any divergence
  anywhere in the 500-bar window”; once one exists the flag stays true for every subsequent
  bar (249/249 measured, up to ~41 h on 5m). BTC currently shows bearish and bullish
  divergence chips simultaneously.

## State machine / sentinel findings

**F2 (HIGH) — one step per sweep, not per closed bar.**
`SymbolTracker.update()` never checks whether a new closed bar arrived. Feed one identical
snapshot repeatedly and the machine advances on every call:
IDLE→PUMP (sweep 1), PUMP→PLATEAU (2), PLATEAU→ARMED (3), ARMED→TRIGGERED + signal (4),
TRIGGERED→IN_TRADE (5) — all on the same 5m candle. At the observed 83 s sweep cadence that
is a full chain in 5.5 minutes.

Production evidence: journal rows for ICNTUSDT —
`19:40:35 PUMP_DETECTED → PLATEAU_BUILDING`, `19:41:59 PLATEAU_BUILDING → ARMED`
(same 5m bucket, 84 s apart).

**F2b — timeouts measured in evaluations.** `bars_in_state` increments per `step()`;
`armed_timeout_bars=60` elapsed after **61 sweeps ≈ 84 min**, not 60 bars = 300 min on 5m.
Rehydration seeds the same counter from elapsed *bars* (`(now-ts)/bar_ms`), so semantics
change after every restart. Sweep cadence is also variable (83–84 s observed), making state
timings non-reproducible.

**F3 (HIGH) — IN_TRADE is terminal.** `features_from_snapshot()` hardcodes
`"trade_closed": False`; nothing else sets it, and no timeout applies to `IN_TRADE`.
Once a symbol reaches IN_TRADE it never leaves (demo: 5 subsequent steps all IN_TRADE), and
rehydration restores IN_TRADE after restart. Net effect: at most one signal per symbol ever.

## Live event semantics

**F4 (MEDIUM).** `has_bearish_div`/`has_bullish_div` = “a divergence exists in the fetched
window”. Measured on BTC: after the first appearance the flag was true on 249/249 bars;
on 5m that is up to ~41 h of “BEARISH_DIVERGENCE”. The live snapshot currently reports
`BEARISH_DIVERGENCE` (last bear div 54 bars old) **and** `BULLISH_DIVERGENCE` and
`FUNDING_EXTREME` at the same time. `ARMED` can therefore be driven by stale or
contradictory evidence. Recommendation: publish divergence age; require the confirming
RSI pivot within N bars (e.g., 12) for the event and for ARMED; rank/suppress contradictions.

## Operations

**F1 (HIGH) — pipeline offline.** Only uvicorn is running (PID 1102355, started Oct 19
~00:08 EDT). Sentinel, recorder, CVD, book, stream, watchdog are absent. All logs stop at
**2026-10-17 20:24 UTC** (16:24 EDT) — consistent with a WSL/session shutdown, not a code
crash (no tracebacks). `/api/signals` reports 10 rows, newest **52.7 h old**; last state
ICNTUSDT = IN_TRADE. No alerts can fire.

**F5 (MEDIUM) — stale journal looks live.** `renderSignals()` sets `signals-upd` to the
*request* time every 15 s and row timestamps use `toLocaleTimeString()` with no date. A
two-day-old row reads like “4:11:11 PM” today. Recommendation: show row age/date and a
“sentinel offline since …” banner based on newest row age (or a health endpoint).

**Bottom line:** the algorithms are implemented correctly and causally, but there is no
validated edge (documented KILLs), the signal service has not been running for two days, and
its bar/state semantics must be fixed before restarting it — otherwise journal transitions and
timeouts are misleading.
